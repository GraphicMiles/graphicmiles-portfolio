What it is

Tessera sells agent workflows that settle on-chain, so the page has to do two jobs at once: prove the work is bounded by rules, and make a dark technical product feel like something you want to touch.

The build is one HTML file with no framework and no runtime dependency. It carries its own typefaces, its own drawing code and every piece of state it needs, so it opens from any static server and the deployed page is the file itself.

The hard part

Two canvases that have to agree with the layout. The hero draws a pixel field that rises as you read, and the same treatment closes the page under the final call to action. Both are sized from the element they sit on and repaint on resize, so the field has to keep its ground line level with the copy at every width instead of being a fixed image.

Words with weight. The section after the hero is not a grid of tags. Each word is a physics body with walls, colliders and a pointer constraint, so visitors can drag and throw the vocabulary of the product while the section heading stays readable underneath. It pauses when it scrolls out of view or when the visitor asks for reduced motion.

A timeline that is driven, not decorated. The workflow section pins a large step counter and steps it from scroll progress, then highlights the matching step in the list beside it. Everything is derived from scroll position, so jumping, resizing or reloading mid-page lands on the correct step instead of a stale one.

An access request that behaves like a form. The brief is built from five dropdowns, a custom calendar that disables past dates, and three text fields. Submitting with anything missing moves focus to the empty part and says which one it is; a complete brief prints a copyable summary. It never pretends to send, because there is no backend behind it.

Stack

HTML, CSS custom properties and vanilla JavaScript in one document. Canvas 2D for the pixel fields and the workflow clock, and matter-js for the word pile, inlined so the page stays a single file. Playwright for the audit across the three widths and for driving every control.

Limits

This is a front-end build, not a product. There is no account, no wallet connection and no backend: the access request prepares a summary you can copy, and the chat answers from a fixed set of replies about the page itself. Nothing is sent anywhere.

The product name, copy and pink accent are a design study. The page is served noindex because it is not a real service, and the words in the pile are decorative physics, not links.
